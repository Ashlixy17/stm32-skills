# 可靠性与验证补充

本文件是结合嵌入式开发风险补充的检查要求；不代表用户已经批准增设 RTOS、看门狗、日志系统、故障处理框架或修改现有硬件策略。仅针对任务影响的路径检查，不借机扩大修改范围。

HAL、初始化、IRQ 和 DMA 具体检查见 [固件开发流程](firmware-development.md)；运行故障定位见 [调试取证流程](debugging.md)。本文件负责消费端状态、时间/数值边界及验证层，避免重复维护同一套外设规则。

## 数据与安全状态

- 消费者须区分事务成功、数据完整与数据有效；不把旧数据、全零或默认值伪装成有效新数据。故障处理中的有意终止路径需说明输出状态和恢复方式。
- 采样值具有有效性和新鲜度语义；丢帧、失联、未标定与过期要能被消费者识别。阈值来源于已确认设计，不能随意发明。
- 设备输出的启动条件、故障状态及恢复条件由当前设计决定；不因“编译通过”改变既定保护。电平极性、有效范围和切换时序须有当前器件与接口依据。
- 修复输入故障后，明确历史数据、缓存、滤波及其他有状态处理如何恢复；避免无效数据持续触发旧命令。具体故障处置策略从当前需求确定，不从参考应用直接复制。

## 共享状态

- 帧内容、长度、序号与有效标志要对应同一次发布；单个字段可原子读写不意味着整个结构体或“检查后清标志”的过程一致。
- 临界区保持短小，保存并恢复进入前的中断屏蔽状态；不能无条件重新开中断破坏上层状态。RTOS 工程使用适合当前任务/ISR 上下文的同步 API。
- 涉及 FreeRTOS 才检查 FromISR API、可调用系统 API 的 IRQ 优先级、队列满、超时与栈；不向裸机工程默认引入 RTOS。

## 时间与数值

- 调度和超时考虑无符号 tick 回绕，通常以同宽无符号差值判断经过时间，并明确允许的最大间隔；不直接用 `now >= start + timeout` 跨回绕比较。
- 使用循环计数器差分时核对实际位宽、模数与两次读取之间允许的最大变化；采用半范围判向方法时说明其成立条件。
- 采样值、计数、时间及换算后的接口写清单位与范围；没有换算依据或有效标定时报告原始值，不把原始计数包装为已校准物理量。
- 输出有与接口匹配的范围检查；除零、负值转无符号、乘法溢出、浮点非有限值及有状态算法的边界按实际输入范围处理。
- 时钟、定时器频率和采样周期以当前时钟树、分频和触发链计算，不默认 TIM 时钟恒为总线两倍；变化后复核控制周期与通信时序。
- 浮点、堆分配、栈数组与日志按目标 FPU、编译选项、RAM 和实时性预算评估。不要在小改动中自行切换浮点 ABI、内存布局或堆策略。

## 按影响选择验证

| 修改内容 | 所需验证 |
|---|---|
| 仅技能/说明文档 | 格式、引用、与现场规则的对应关系；不为凑检查构建固件 |
| 业务 C/H、宏或接口 | 差异审查、相关主机测试（存在或确有必要时）、实际目标构建 |
| 状态机、协议、控制算法 | 正常输入加受影响的故障/边界回放；实际构建；列出实物待测项 |
| IOC/时钟/引脚/外设配置 | 对应配置授权、CubeMX 生成、IOC/生成结果/资源冲突复核、实际构建 |
| 链接/启动/编译器/构建目标 | 实际完整构建，检查目标器件、链接段、启动文件与诊断 |
| DMA/中断时序/电气行为 | 源码与构建只能做前置验证，实物结论须有设备观测 |
| 仅离线故障分析 | 核对映像/符号及原始记录，明确未连接、未复现或未证明之处 |

- 测试验证可观察行为和边界，不只匹配函数名或实现文本。只运行与变化相关的检查，必要时补充有意义的测试。
- 工具脚本必须从当前文件中发现并核对，不把历史路径当作现存事实，不自动恢复用户已删除的脚本。
- 记录构建目标、配置、实际命令、时间、退出状态及编译链接诊断。确认产物由本次构建产生，不以旧日志或旧 HEX 代替。
- 环境缺失或外部设备不可达时记录具体原因和未完成项；验证失败先修复，不伪报通过。不要为获得通过而削弱断言、关闭警告或更改无关目标。
- 仅在任务或工程要求归档时执行，产物类型、命名和位置遵循该工程约定；归档失败单独报告，不能因编译成功就宣称要求的归档已完成。
