# STM32 调试取证流程

用于故障分析、运行状态检查及授权的设备调试。使用当前已安装且适配该工程的工具；本技能只提供流程，不附带调试服务器、探针驱动或上游脚本。

## 1. 区分分析产物与操作设备

- 读取源码、构建日志、ELF/AXF 符号或已导出的寄存器快照，可以先做离线分析；没有设备观测不得写成实物结果。
- 连接/暂停/单步/复位/烧录/修改内存或寄存器属于不同操作，按用户实际调试授权执行；已有授权不重复询问。仅查看源码不构成自动烧录或重启设备的授权。
- 首次接入前确认工具会 attach 还是 reset/load。已有故障现场先记录，不能为了方便连接就重启、重烧或启动第二个调试服务器。
- 设备运行时，确认暂停 CPU 对外设、通信、看门狗及外部输出的影响；不能默认所有外设随 CPU 一起停止。依据当前设计选择观测方式。

## 2. 建立源码、固件和符号的对应关系

| 对象 | 需要确认的事实 |
|---|---|
| 源码 | 仓库版本、未提交改动、相关配置与实际源文件路径 |
| 构建目标 | MCU、Debug/Release 或目标名、编译器版本、优化和调试信息设置 |
| ELF/AXF | 本次目标对应的可执行映像、符号和链接地址，不使用另一目标或旧文件 |
| HEX/BIN | 与该次构建对应的烧录映像；本身不能替代源码级调试符号 |
| 运行固件 | 通过既有烧录记录、内存校验或已有构建标识建立对应关系；时间戳只作为线索 |
| SVD | 对应实际器件/系列与版本，用于地址和位域显示；行为语义仍查参考手册和勘误 |

无法确认运行版本时先注明“映像对应关系未证实”，不要把源码行号解释当成确定事实。缺少调试信息不等于不能读寄存器，但会限制变量、行号和调用栈的解释。

## 3. 选择现有工具

- 优先使用当前工程的调试目标与可用接口；IDE、CMSIS 调试服务、GDB/OpenOCD、探针工具等按实际配置选择，不限定供应商，不要求全部安装。
- 检查探针、目标器件、供电/连接、调试协议和当前会话。连接失败时先核对报错与会话归属，不全局终止所有同名进程、不默认擦除芯片或降低保护设置。
- 外部示例中的脚本、端口、SVD 路径、CPU 频率和命令不是本工程默认值。未实际发现工具就不编造调用结果。
- 先尝试能够回答当前假设的最小观测；同一连接错误反复出现且无新证据时停止盲目重试，记录错误、已核对内容及所缺条件。

## 4. 从现象提出可检查的假设

记录实际现象、复现条件、频率、预期行为和最近相关改动。每轮观测只回答一个具体问题，例如：

- 采样没有更新：启动调用是否成功、DMA 是否计数、IRQ 是否进入、完成回调是否发布新序号、消费者是否收到新帧？
- 程序卡死：PC 停在哪个等待/循环，退出条件是什么，时基是否推进，句柄是否忙，是否进入异常？
- 输出异常：输入帧是否有效，单位/方向是否一致，限幅前后值是什么，谁最后修改了命令？

“现象 → 假设 → 观测点 → 结果 → 判断”逐步缩小范围。根因未找到时不能把临时加延时、改参数或增加重试当成已定位修复。

## 5. 组合调试手段

| 手段 | 回答的问题 | 使用边界 |
|---|---|---|
| 断点/条件断点 | 哪个调用或状态转换被执行，何时进入错误路径 | 会暂停程序并改变时间关系，不用单步结果证明实时性能 |
| 观察点 | 哪个 CPU 访问导致关键地址/变量变化 | 核对硬件支持、数量、宽度和作用域；不把未命中当作 DMA 未写入的证明 |
| 变量与表达式 | 输入、状态、计数和输出是否符合当前假设 | 先核对符号、作用域、类型、优化和读取时刻；不调用带副作用的目标函数求值 |
| SVD/寄存器 | 外设是否启用、状态/计数/中断/错误标志是什么 | 核对读副作用，不能把读清标志或 FIFO 数据端口当无副作用监视值 |
| 调用栈、PC/LR/SP | 从哪里来到当前执行位置、是否异常跳转 | 栈损坏或优化可能限制回溯；注明帧和寄存器的采集上下文 |
| SWO/串口/逻辑分析仪 | 运行中的事件顺序、信号及时间关系 | 使用实际时钟和已配置通道；限频日志，未配置日志通道不自动增设 |

- 看不到变量时先检查调试信息、优化、所在栈帧和符号限定；不要为调试便利删除 `static`、改成全局或给所有变量加 `volatile`。
- 观察点尽量选有明确地址的小对象。硬件资源不足时缩小范围；软件观察点可能严重改变执行速度，不能默默用于实时性验证。
- 寄存器地址、访问宽度、读写语义从当前器件资料核对。SVD 用于解码，不保证所有外设寄存器都能安全反复读取。
- SWO 的频率、引脚及可用性以当前硬件为准，不照抄外部示例值。通道不可用时报告限制，不把无输出直接判为代码没运行。

## 6. 异常与现场保留

- HardFault 等异常先保留工具可读到的 PC/LR/SP、核心状态、调用栈和该核心支持的故障状态寄存器；例如支持时读取 CFSR/HFSR，地址寄存器只在对应有效位成立时解释。
- 区分异常处理器当前寄存器与异常入栈的被打断现场；按异常返回信息和当前核心规则识别 MSP/PSP 及栈帧布局，不硬套固定偏移。
- 栈不可读、已损坏或回溯不可靠时明确标注。一次寄存器值只是观测，需结合有效位、指令和访问对象判断原因。
- 使用已有复位原因、错误计数或构建标识；新增持久化日志、Fault 处理代码及修改生成区仍需遵守业务设计与编辑边界。

## 7. 验证结论与收尾

- 修复前后使用相同触发条件验证相关行为。取消为排查临时设置的断点/观察点，清理由本任务创建且不再需要的会话；不接管或关闭用户其他调试会话。
- 保留已有日志与快照。调试记录只写任务需要的信息；公开分享前不携带本机用户路径、凭据或无关内存转储。
- 调试证据模板可直接填在任务交付中，不要求每次创建额外文件：

| 字段 | 记录内容 |
|---|---|
| 现象与条件 | 实际输入、复现步骤、期望与观测差异 |
| 版本与目标 | 源码版本/改动、目标配置、映像与运行版本的对应证据 |
| 工具与操作 | 探针/调试工具、attach/reset/load、暂停或持续运行状态 |
| 假设与观测 | 断点位置、变量/寄存器/调用栈等实际结果及采集时机 |
| 判断与限制 | 已证实、已排除、仍待验证的内容，调试对时序的影响 |
| 修改与复验 | 实际差异、同条件结果、构建及实物验证范围 |

只形成离线分析或未复现故障时如实报告，不写“问题已解决”。
